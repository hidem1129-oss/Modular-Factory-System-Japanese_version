# Grafana：履歴の可視化

I²C DebuggerがSQLiteへ保存した観測結果を表示します。ハードウェアを直接読まず、制御指示も出しません。

## 何を確認するか

| 表示 | 読む情報 | 確認したいこと |
|---|---|---|
| ノード状態の時系列 | node_snapshotsなど | いつREADY、BUSY、通信断などを観測したか |
| イベント一覧 | event_logs | 直近にどの状態変化があったか |
| 状態の継続時間 | state_segments | 観測された状態がどれだけ続いたか |
| セッション | monitor_sessions | どの試行の記録か |
| 電源の推移・比較 | power_port_snapshots | 電圧、電流、算出電力がどう変化したか |

## セッションと時間範囲

監視セッションを使うと、別々のデモや試験の記録を区別できます。ただし、すべてのパネルが同じ方法でセッションを絞るとは限りません。現在の電源分析パネルは主に、選択セッションに対応するダッシュボード時間範囲を使用します。

比較するときは、セッション、時間範囲、real / mock、ポート割り当て、設定条件を合わせて確認します。

## SQLと設定資料

英語版の[Grafana資料](https://github.com/hidem1129-oss/Modular-Factory-System/blob/main/Software/Grafana/README.md)から、状態タイムライン、イベント、ERROR / ESTOP、最近のセッション、ポート・主幹、電力ランキング、統計の各SQL例へ進めます。

SQLの条件は、保存されているテーブルと列、時刻、セッション、表示したい情報に合わせます。日本語版は読み方を説明し、SQLと設定資料は英語版で管理します。

## グラフの解釈

平均や最大値は保存された観測サンプルから得た値です。ポーリング間に発生した瞬間的なピークをすべて捉えた値とは限りません。欠測や観測周期も比較に影響します。

電源測定点は負荷端子の上流なので、グラフの電力は端子での精密な消費電力と区別します。測定位置は[Power Monitor Board](../../Hardware/Power_Monitor_Board/README.md)で説明しています。

グラフ上の負荷しきい値は監視上の目安であり、ヒューズ、電源保護、ファームウェア停止を置き換えません。現在はローカルSQLiteと手動設定したダッシュボードを前提とし、本番向けのアクセス制御設計は対象外です。
